# THE SYSTEM IS ALIVE

## Surface / concept
An editorial exploration, not a template. An oversized, left-aligned professional identity intersects a cobalt mechanical reactor. A thin registration grid, printed captions and chapter markers turn engineering into a readable visual language. Light, paper-like sections interrupt the dark field to create pacing.

## Reference analysis
Stas Bondar: the retrieved document exposes large decomposed typography and image-led case navigation; borrow typographic hierarchy and continuity, not lettering/layout/assets. Hardik Bhansali: explicit scene chapters, narrative pacing and a separately invited webcam experience; borrow progressive immersion, not its birth story, branding or art. Text extraction does not prove timing or shader behavior, so those are treated as brief requirements rather than observed claims.

## Typography / color
Barlow Condensed (600/700) for compressed architectural display, Space Grotesk (400/500/600) for readable editorial copy, IBM Plex Mono (400) for annotations. Self-hosted WOFF2 through Fontsource. Background #080808, panel #111113, paper/text #F1EFE9, secondary #A6A6A6. Cobalt #2957FF as the single electric accent; accessible accent text #8FAAFF. CSS variables own the palette.

## Motion language
Reveal, assemble, resolve. Masked headings, restrained perspective, image continuity through Astro View Transitions, GSAP/ScrollTrigger section sequencing and quickTo pointer response. A shared MotionManager owns input, velocity, viewport and the GSAP ticker. Lenis is desktop-only, never prevents normal touch/keyboard navigation. No artificial loading delay. Reduced motion presents the complete static composition.

## WebGL
One lazy-loaded renderer. Procedural rings, structural struts and shader-displaced particles describe a code reactor, disperse toward the manifesto and regroup at contact. DOM-synchronized image planes share that renderer. No external models, textures or postprocessing chain. HTML content is authoritative and remains visible if graphics fail.

## Architecture
Astro static routes, typed data in src/data, semantic section components, separate animation/webgl/performance modules. One portfolio case study documents this actual implementation; unprovided employment and project details are never fabricated. Additional projects and employment records can be supplied through typed data. No invented metrics or contact addresses.

## Performance / accessibility
Dynamic imports, one animation scheduler, cached rectangles updated on resize, clamped DPR, IntersectionObserver and hidden-page pause, deterministic cleanup on Astro navigation. Physics is one lazy desktop-only moment. Mobile uses native scroll, smaller particle budgets and an editorial experience list. Native dialog palette, keyboard controls, skip link, focus treatment, screen-reader text and reduced-motion fallbacks.

## Release conditions
Check Astro/TypeScript, build, browser interactions, six viewport widths, no-JS/reduced-motion content, Chromium/Firefox/WebKit, axe and Lighthouse. WebKit testing is not a claim of testing real Safari on macOS/iOS. PUBLIC_SITE_URL must be set to the final owned domain before deployment; email/LinkedIn/resume remain absent until supplied. Hand tracking and sound are intentionally optional and off.
